1. 打开 Supabase 的 SQL Editor，运行同目录 `20261020_watch_behaviors.sql` 全部内容一次。不要重新运行旧版 schema.sql。此脚本新增行为数据列、扩展 dramify_export，并保存旧版数据的受保护快照，不删除研究记录。
2. 解压 `Dramify-观看界面更新.zip`，将其中网页文件覆盖到 GitHub 仓库根目录。SQL 文件在 Supabase 执行即可，不需要靠上传 GitHub 来执行。
3. Pages 部署完成后，使用 TEST 昵称分别输入两个访问码验证，确认数据进入 dramify_export，再正式收集。

## 新的行为定义

- choice：是否已付费解锁，1/0。一次 20 coins 解锁整部剧的 50 集，不重复扣费，不提供取消购买。
- liked / saved / shared：当前点赞、收藏、转发标记，1/0，均免费且可取消。
- views：进入该剧观看页的次数，重复进入或刷新观看页均算一次；点赞等组件重绘不增加。
- like_count / save_count / share_count：累计将该行为选为“是”的次数，取消后再次选中会再加一。
- rating：想看程度 1–5，未评分为空。
- 所有未展示的 a/b 版本仍为空。
- LikedCount / SavedCount / SharedCount：当前选中的不同剧集数量。
- BrowsedCount：进入过观看页的不同剧集数量；BrowseVisits 为观看页进入总次数。
- UnlockedCount：已解锁数量；LikeActions / SaveActions / ShareActions 为对应的累计操作次数。
- BehaviorEvents：行为事件时间、剧集 ID、版本和状态，便于后续重新计算指标。
- InterfaceVersion：新界面为 watch-v3，旧记录为 preorder-v2，分析时请分开。

## 旧记录迁移

旧版预订仅转为免费收藏，并将本地余额恢复到 100；不视作新版付费解锁。数据库迁移脚本先将旧研究记录备份至 dramify_preorder_archive_20261020，普通访客无权读取。不要将旧版预订的 choice 与新版解锁 choice 混合分析。
